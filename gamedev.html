Personal Projects

Oaksnob

This game is the result of me being driven by the desire to complete at least one small video game entirely by myself. This psychological-horror, 2D puzzle game is written in Python and utilizes the pygame module. I created all of the art/graphics using MS Paint, the audio (sound effects and music) using LMMS, the puzzles, and the plot. This game is heavily inspired by Sokoban, a variation of which I first played on a Ti-83 graphing calculator. There are 40 levels and 4 major achievements, 2 of which can only be achieved by "hacking the game" as they are otherwise mutually exclusive... Behold! (viewer discretion advised):

Oaksnob Level Editor

To aid in my development process and also allow the potential for others to design their own levels, I created a level editor in pygame where you can click on tiles to cycle through the different game objects, and then you can export the created levels to text files which could be used in the game in place of other levels.

Archer

Having completed Oaksnob and realizing how much extra time it takes to design puzzles, I decided to switch gears and create a real-time, action-based game which can be played with a controller/gamepad. Still using Python and pygame, although unfinished, this game consists of an archer who can move in all directions and shoot in 16 different directions using the joysticks. Enemies chase the player and dungeons are procedurally generated in such a way that the game can always be completed, despite needing access to certain rooms prior to other rooms. The intention is to implement quasi-puzzle gameplay using color-mixing, yet with the main gameplay consisting of quick thinking, reflexes, resource management, and action-based skills.

Tarot

Due to the struggles inherent to creating executables which can only be run on computers and not mobile devices, thereby significantly limiting the number of people I could share my game with, I decided it would be a good idea to create a game using JavaScript so that anyone can play in a browser from any device. This game is a work in progress, and is actually going to be a minigame within a larger RPG-style game that I have planned. This will be a card game based on Tarot which borrows mechanics from Rummy and Carcassonne.

2x2x2 Cube Simulator

Inspired to discover my own algorithm for solving a 2x2x2 Rubik's Cube in the longest manner possible, such that every permutation is eventually seen, I coded a simulation where you can rotate the sides and essentially play with a digital version which can always be reset. I first coded this in Ruby, but ultimately switched to Python due to familiarity. I am yet to discover the imagined algorithm though...

Notable Academic Projects

Checkers

Using Java, JavaFX, Threads, and Client and Server Sockets, I implemented the game of Checkers. The game consisted of either a console-based user interface or a GUI. There also existed an automated feature where you could watch the computer play against itself.

Follow, Flowers, and Minigames

Using gRPC and an AWS EC2 instance, we implemented 3 console-based services on a server which could be accessed by a client. The "Follow" service consisted of the ability to register, add a user, follow a user, and view who a user is following. The "Flowers" service consisted of a garden simulator, wherein you could plant a flower, view the flowers, water a planted flower, and care for a blooming flower. Both Follow and Flowers were implemented according to provided protocols. For the "Minigames" service, I created my own protocol, and in this service you could view "How to Play", play "speedTyper", or play "fastMaths". "How to Play" printed the instructions for each game. "SpeedTyper" consisted of a game where you have to type a series of words as fast as you can, and you scored points by typing correct characters before the timer runs out. "FastMaths" consisted of an infinite loop of math problems, and you are trying to solve as many as possible before the timer runs out. You scored points based on the literal numeric solutions to the problems (provided that the answers given were correct).

Location Guessing Game

Using Java Swing, Sockets, and a custom JSON protocol, implemented a location-guessing game where the client receives images from the server (encoded in Base64). The client could choose to go left or right and this would display new images taken to the right or left, etc. The client could then try to guess the location and score points.
